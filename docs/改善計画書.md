## Phase 1: 復習データ・学習履歴の Supabase 同期

### 方針

- 既存の `user_stats` テーブルと同じ「**1ユーザー1行・JSONB・upsert**」方式を踏襲する
- テーブルは **1つだけ追加**し、復習リスト・学習ログ・トリビア・バッジをまとめて持つ
  （リクエスト数と実装量を最小化。1問1行にはしない＝行数爆発を防ぐ）

### テーブル設計

```sql
create table user_learning_data (
  user_id    uuid primary key references auth.users(id),
  wrong      jsonb default '{}',   -- 間違えた問題（Phase 2 の SRS フィールドを含む）
  quiz_log   jsonb default '{}',   -- 日別学習ログ（直近120日分のみ保持）
  trivia     jsonb default '[]',   -- トリビアカード所持ID
  badges     jsonb default '[]',   -- バッジ所持ID
  updated_at timestamptz default now()
);

-- RLS（必須。忘れると他の生徒のデータが読める）
alter table user_learning_data enable row level security;
create policy "own row select" on user_learning_data
  for select using (auth.uid() = user_id);
create policy "own row insert" on user_learning_data
  for insert with check (auth.uid() = user_id);
create policy "own row update" on user_learning_data
  for update using (auth.uid() = user_id);
```

### 同期ロジック

| タイミング | 処理 |
|---|---|
| ログイン直後（1回） | サーバーからダウンロードし、ローカルと**マージ**して localStorage に反映 |
| クイズ1セッション終了時（結果画面表示時に1回） | localStorage の内容をまとめて upsert |

**マージ規則（複数端末対応の要）**
- `wrong`: サーバーとローカルの**和集合**（間違い記録は両方残す。消えるより安全側に倒す）
- `quiz_log`: 日付キーごとに比較し、**回数が多い方**を採用
- `trivia` / `badges`: **和集合**（獲得したものは消えない）

> 既存 `user_stats` の「ポイント合計が大きい方優先」より安全な方式。
> 将来的に `user_stats` 側も同様の方式へ揃えることを検討（本計画のスコープ外）。

### 無料枠への影響（試算）

| 項目 | 無料枠上限 | 想定使用量 |
|---|---|---|
| DB 容量 | 500 MB | 生徒200人 × 約50KB = **約10MB（2%）** |

## Phase 2: 間隔反復（忘却曲線）による復習

### 方針

間違えた問題に「次回復習日」を持たせ、**1日 → 3日 → 7日 → 14日** の間隔で再出題する。
14日間隔をクリア（合計4回連続正解）したら「定着」としてリストから卒業する。

### データ形式（Phase 1 の `wrong` フィールドを拡張）

```js
// localStorage 'phy_quiz_wrong' / Supabase wrong カラム
{
  "part1": {
    "11563": { "next": "2026-06-13", "streak": 0, "last": "2026-06-12" }
    //         next: 次回復習日, streak: 連続正解数, last: 最終解答日
  }
}
```

- 間違えた → `streak = 0`、`next = 翌日`
- 復習で正解 → `streak + 1`、`next = 今日 + [1, 3, 7, 14][streak]` 日後
- `streak` が 4 に到達 → リストから削除（卒業）

> **互換性**: 現行形式は `{ "part1": [11563, ...] }`（ID配列）。
> 読み込み時に旧形式を検出したら新形式へ自動変換する移行処理を入れる。

### UI 変更

| 画面 | 変更 |
|---|---|
| トップ画面 | キャラクターの吹き出し等に「今日の復習 ◯問」を表示。タップで復習モードへ直行 |
| 復習モード | 「今日が復習日の問題」を優先出題（従来の全問復習も残す） |
| 復習正解時 | 「あと◯回正解で定着！」の表示（卒業が見えるとモチベーションになる） |

### Phase 2 確認チェックリスト

- [ ] 間違えた問題が翌日「今日の復習」に出る
- [ ] 復習で正解 → 3日後に再出題される（端末の日付を進めて確認）
- [ ] 復習で不正解 → 間隔が翌日にリセットされる
- [ ] 4回連続正解した問題がリストから消える（卒業）
- [ ] 旧形式（ID配列）のデータが壊れずに新形式へ移行される
- [ ] 復習対象0問のとき、トップ画面の表示が邪魔にならない

## Phase 3: 連続学習日数（ストリーク）

### 方針

既存の日別学習ログ（`phy_quiz_log`）から連続日数を算出して表示するだけ。
**新規データ・新規テーブルは不要**（Phase 1 で同期済みのログを使う）。

### 仕様

- 「1日1問以上解いたら学習日」としてカウント
- トップ画面に「🔥 ◯日連続」を表示。途切れても責めない文言にする（例: 途切れたら単に非表示 or「今日から再スタート！」）
- 既存バッジと連動: 「7日連続」「30日連続」バッジを `badges.js` に追加

### Phase 3 確認チェックリスト

- [ ] 連続日数が日別ログから正しく計算される（日付またぎ・タイムゾーン）
- [ ] 1日空くとリセットされる
- [ ] 連続日数バッジが正しく付与される
- [ ] ログが空の新規ユーザーでエラーにならない

## 3. 共通の運用ルール・リスク

| 項目 | 内容 |
|---|---|
| **Supabase 一時停止** | 無料プランは約1週間アクセスがないと自動停止する。**長期休み明けの前日に教員がアプリを一度開く**（またはダッシュボードで再開）ことを運用ルールとする |
| **キャッシュ更新** | 各 Phase のリリース時に `sw.js` の `CACHE_NAME` を必ず上げる（忘れると生徒に反映されない） |
| **RLS** | テーブル追加時は必ず RLS ポリシーをセットで作成する |
| **同期失敗時** | ネットワークエラーでも学習自体は止めない（localStorage 優先で動作し、次回オンライン時に同期） |
| **個人情報** | 同期するのは問題ID・回数・日付のみ。氏名等は新たに保存しない |
| **script.js の肥大化** | Phase 1〜2 実装後、必要に応じて「データ層・クイズ進行・UI」の3分割を検討（別計画） |
